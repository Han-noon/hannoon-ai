# 토픽 키워드·요약·연관 토픽

기존 분류 후 실행하는 독립 도구입니다. 로컬 Ollama `qwen3:4b`와 Node.js 22 이상을 사용하며 별도 npm 의존성은 없습니다. 기존 Python 파이프라인과 배포 설정은 변경하지 않습니다. 실행 서버에 Node와 Ollama가 별도로 준비되어 있어야 합니다.

DB는 `hannoon-supabase` #39의 기존 RPC를 사용합니다. **새 마이그레이션이나 데이터 재적재가 필요하지 않습니다.** 카드 요약은 `topics.ai_summary`에 저장하며 분류용 `topics.summary`는 유지합니다. 공개 `get_topic_enrichment`의 숫자형 ID도 그대로입니다.

## 실행

1. `config.example.json`을 `config.json`으로 복사하고 `topic_ids`에 실제 DB ID를 문자열로 설정합니다(최대 10개). 분류 코드 `T01`이 아닌 DB ID입니다.
2. 서버 환경변수 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`를 설정합니다. 키는 브라우저나 Git에 넣지 않습니다.
3. 이 디렉터리에서 실행합니다.

```sh
node cli.mjs preview # 생성만 수행, DB 쓰기 없음
node cli.mjs once    # 검증된 전체 결과 저장
node cli.mjs watch   # 기본 60초마다 입력 변경 확인
node --test tests.mjs relations.test.mjs
```

기존 데이터가 바뀌면 재생성합니다. v2 버전으로 인해 v1 결과도 다음 실행에서 재생성됩니다. 미리보기 결과를 확인한 뒤 저장하세요. 운영 실행/스케줄 등록은 별도이며 PR 머지만으로 자동 실행되지 않습니다.

## 연관 토픽 판단

- 생성 요약을 관계의 근거로 재사용하지 않고 두 토픽씩 원본 이벤트 제목을 비교합니다. 제목은 묶음으로 모두 확인합니다.
- 후보 근거 ID를 각 토픽에 따로 제한하고 실제 제목 인용인지 검사합니다.
- 후보의 원본 요약/핵심 내용을 다시 검수합니다. 상세 내용이 없는 경우 제목을 사용합니다.
- 저장되는 설명은 검수에서 선택한 원문 발췌 두 개입니다. 자유 생성한 인과관계 설명을 저장하지 않습니다.
- 무관하면 연결하지 않으며 특정 토픽명·ID·정답 쌍을 고정하지 않습니다. 카드당 최대 3개, 초과 시 숫자 ID 순으로 먼저 검증된 쌍을 유지합니다.
- 형식/근거 오류는 한 번 재시도합니다. 계속 실패하거나 모델/입력 한도 오류가 있으면 전체 저장을 중단하고 이전 DB 결과를 보존합니다. 오류를 빈 정상 결과로 바꾸지 않습니다.

토픽·이벤트는 자료이며 자료에 포함된 지시는 따르지 않도록 프롬프트를 분리합니다. 모델 판정은 완벽하지 않으며 제목에 드러나지 않는 관계는 누락할 수 있습니다. 저장 전 미리보기 검수가 필요합니다.

## 검증 범위

`validation.json`은 10개 토픽/885개 이벤트의 보관된 이벤트명·관련 기사 제목으로 실행한 회귀 확인입니다. 관계 45쌍에서 배재고–스타벅스 1쌍이 생성됐고, 격리 DB에서 저장/양방향 조회/기존 summary 보존을 확인했습니다. 이전과 동일한 요약 호출과 변경 없는 후보 호출은 캐시를 재사용했습니다. 운영 DB 전체 본문 평가나 독립 정확도 지표는 아닙니다.

원본 데이터·모델 가중치·키는 포함하지 않습니다. 별도 입력 검사는 다음과 같이 실행합니다.

```sh
node verify.mjs /path/to/snapshot.json /path/to/output.json
```

입력 형식은 `topic_enrichment_snapshot` 응답의 `topics: [{id,title,events:[{id,title,summary,core_content}]}]`입니다. 결과 파일에는 원문 일부가 들어갈 수 있으므로 공개 업로드 전에 확인하세요.
