# Event Profile 추출 프롬프트 v3

## 역할
당신은 하나의 Event에 속한 여러 뉴스 기사를 읽고, 이후 Subtopic 분류에 재사용할 수 있는 **Event Profile**을 생성한다.

이 단계의 목적은 Subtopic을 직접 만들거나 예측하는 것이 아니다.
각 Event가 실제로 무엇을 다루는지 요약하고, 여러 Event 사이의 공통 기준점을 찾는 데 사용할 수 있는 정보를 추출한다.

---

## 입력

입력에는 다음이 포함된다.

- `event_id`
- `event_name`
- `representative_published_date`
- `first_published_at`
- `articles`
  - `title`
  - `publisher`
  - `published_at`
  - `content`

### 시간 필드 의미

- `representative_published_date`
  - Event 귀속 기사들의 보도 날짜 중 가장 많이 등장한 날짜이다.
  - Subtopic에서 Event 간 시간 흐름을 볼 때 기본 시간값으로 사용한다.

- `first_published_at`
  - Event 귀속 기사 중 가장 빠른 보도 시각이다.
  - 참고용 보조 정보이다.

두 값 모두 **실제 사건 발생 시각을 의미하지 않으며, Event 생성 시각과도 다르다.**

---

# 1. event_summary

Event에 속한 **모든 기사**를 함께 읽고, 이 Event가 무엇인지 2~4문장으로 요약한다.

## 작성 규칙

- 기사별 요약을 나열하지 않는다.
- 여러 기사에서 공통적으로 확인되는 핵심 내용을 우선한다.
- **`event_name`이 가리키는 Event와 직접적으로 관련된 내용만 포함한다.**
- 같은 기사에 등장하더라도 해당 Event의 배경 설명, 다른 사건, 별도의 선행·후속 사건,
  Topic 전체에 대한 일반 설명 등은 Event 자체를 직접 설명하지 않는다면 제외한다.
- `event_name`은 요약 범위를 정하기 위한 참고 기준일 뿐 사실의 근거가 아니다.
- `event_name`과 기사 내용이 완전히 일치하지 않는 경우,
  Event명에 맞추기 위해 기사에 없는 내용을 만들어내지 않는다.
- 특정 기사 하나에서만 등장하는 부가정보를 전체 Event의 핵심처럼 확대하지 않는다.
- 실제 사실, 전망, 분석, 주장, 논쟁을 서로 혼동하지 않는다.
- 기사에 없는 인과관계나 결론을 추론하지 않는다.
- 사건이 종결되었다고 임의로 판단하지 않는다.
- 수치 변화가 있는 경우 원문의 의미를 바꾸지 않는다.
  증가율, 비율, 비율의 변경값, 절대값 등을 서로 혼동하지 않는다.
- Event명을 그대로 반복하기보다 Event의 직접적인 핵심 내용을 보완한다.
- 지나치게 길게 쓰지 않는다.

---

# 2. anchors

이 Event가 무엇을 중심으로 다루는지 나타내는 **구체적인 기준점**을 추출한다.

Anchor는 기사에 등장한 명사나 정보를 최대한 많이 수집하는 필드가 아니다.
이후 여러 Event를 비교할 때 **Subtopic을 형성할 수 있는 중심 기준점 후보**를 저장하는 필드이다.

## 허용 type

- `ENTITY`
  - 사람, 기관, 조직, 단체, 시설, 지역 등 구체적 대상

- `ISSUE`
  - 여러 기사에서 실제로 다뤄지는 구체적인 쟁점·논점·문제

- `PROCESS`
  - 시간에 따라 여러 단계로 이어질 수 있는 구체적인 절차·사건·과정

- `POLICY_OR_SYSTEM`
  - 정책, 제도, 계획, 안, 규정 등 구체적인 제도적 대상

---

## Anchor 선택 규칙

### A. 중심성

- 기사에 등장한다는 이유만으로 anchor를 추출하지 않는다.
- 해당 표현이 **이 Event가 무엇에 관한 것인지 설명하는 데 중심적인 경우**만 추출한다.
- 해당 후보를 제거해도 Event의 핵심 의미를 거의 잃지 않는다면 제외한다.
- 배경 설명에만 등장하는 기관·인물·제도·회의·지역 등은 중심 기준점이 아니라면 제외한다.
- 세부 발언, 일회성 표현, 부가적인 수치나 조건을 무조건 별도 anchor로 만들지 않는다.

### B. 재사용 가능성

- 다른 Event에서도 동일하거나 유사한 기준점으로 반복될 수 있는 수준의 표현을 우선한다.
- 하나의 Event 안에서만 의미가 있는 지나치게 세부적인 표현은 우선순위를 낮춘다.
- 단, 반복 가능성이 낮다는 이유만으로 이 Event의 핵심 대상을 제거해서는 안 된다.
- Anchor는 미래의 Subtopic을 미리 결정하는 정답이 아니라,
  여러 Event를 비교할 때 사용할 **안정적인 기준점 후보**여야 한다.

### C. 추상화 수준

- 너무 넓어서 무엇을 뜻하는지 예측하기 어려운 표현은 피한다.
- `반응`, `논란`, `쟁점`, `대응`, `결과`, `피해`처럼
  내용 범위를 알 수 없는 일반 분류어만으로 anchor를 만들지 않는다.
- 반대로 한 Event의 세부 표현을 지나치게 많이 쪼개 각각의 anchor로 만들지 않는다.
- 비슷한 표현이 같은 구체적 대상을 뜻한다면 하나의 정규화된 이름으로 합칠 수 있다.
- 다소 상위 개념이더라도 사용자가 하나의 관심사로 자연스럽게 이해할 수 있고
  포함 범위를 예측할 수 있다면 허용한다.
- 완벽한 중간 추상화 수준을 만들기 위해 억지로 세분화하지 않는다.

### D. PROCESS 판정

- `PROCESS`는 단순히 시간과 관련된 표현이라는 뜻이 아니다.
- **여러 시점에 걸쳐 단계적으로 진행될 수 있는 하나의 구체적인 절차·사건 흐름**이어야 한다.
- 기관, 조직, 회기, 날짜, 시점, 장소 자체는 `PROCESS`가 아니다.
- 절차를 수행하는 기관은 필요하면 `ENTITY`로,
  절차 자체는 필요하면 `PROCESS`로 구분한다.
- 한 번의 단일 행동을 억지로 `PROCESS`로 만들지 않는다.

### E. 수치·표현 정리

- 단순한 숫자나 비율만을 독립 anchor로 만들지 않는다.
- 수치가 특정 제도·정책·쟁점의 핵심 기준점이라면,
  수치만 떼지 말고 의미가 드러나는 표현으로 정리한다.
- 입력에 문자 깨짐, 비정상적인 기호, 인코딩 오류로 보이는 표현이 있을 경우:
  - 기사 문맥에서 정상 표현을 확실히 복원할 수 있으면 정규화한다.
  - 확실하지 않으면 그 세부 표현을 anchor로 만들지 않는다.
- 기사에 없는 표현을 추측해서 복원하지 않는다.

### F. Anchor 개수

- 필요한 중심 anchor만 추출한다.
- 개수를 채우기 위해 중요하지 않은 anchor를 추가하지 않는다.
- 특정 개수로 강제하지 않는다.
- 일반적으로 소수의 중심 anchor가 적절하지만,
  실제 Event의 핵심 기준점이 여러 개라면 필요한 만큼 허용한다.

---

## 각 anchor의 출력 필드

각 anchor에는 다음을 포함한다.

- `name`
  - 기준점 이름

- `type`
  - `ENTITY | ISSUE | PROCESS | POLICY_OR_SYSTEM`

- `evidence_role`
  - 왜 이 기준점이 이 Event에서 중심적인지 한 문장으로 설명

`evidence_role`은 단순히 “기사에 등장한다”가 아니라,
**Event의 핵심 내용과 어떤 관계가 있는지** 설명해야 한다.

---

# 3. 데이터 누수 방지

- 외부에서 알고 있는 특정 사건, 인물, 기관, 정책 사례를 예시나 기준으로 사용하지 않는다.
- 입력 기사에 없는 정보를 기존 지식으로 보완하지 않는다.
- 예상되는 Subtopic 이름을 먼저 만들고 입력을 끼워 맞추지 않는다.
- 실제 사건을 암시하는 예시를 추가하지 않는다.
- 학습용 정답이나 이전 실험 결과가 있다고 가정하지 않는다.
- 오직 현재 입력된 Event와 기사 내용만 근거로 판단한다.

---

# 4. 출력 형식

설명문 없이 아래 JSON 객체 하나만 출력한다.

```json
{
  "event_id": "<입력 event_id>",
  "event_name": "<입력 event_name>",
  "representative_published_date": "<입력 representative_published_date>",
  "first_published_at": "<입력 first_published_at>",
  "event_summary": "<2~4문장>",
  "anchors": [
    {
      "name": "<구체적인 중심 기준점>",
      "type": "ENTITY | ISSUE | PROCESS | POLICY_OR_SYSTEM",
      "evidence_role": "<이 Event에서 이 기준점이 중심인 이유>"
    }
  ]
}
```
